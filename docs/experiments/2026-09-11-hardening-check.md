# SPB 的上界有没有真的触发软子句硬化

日期：2026-09-11 ・ 批次 `runs/debug50_harden`（50 实例 x {CASH, HybridSelective}，30/10，600 秒）
・ 新增字段 `harden_count` / `harden_gap_to_next` / `harden_goal_interval` ・ 提交 `3432a75`

## 1. 机制与口径

`harden_soft_cls()` 的判据是**严格不等式**：权重严格大于 `UB - LB` 的软子句才被硬化，一次可能硬化一整批。
据此新增三个逐轮字段：

| 字段 | 含义 |
|---|---|
| `harden_count` | 已经硬化的软子句数（`soft_cls.size() - top_for_hard`） |
| `harden_gap_to_next` | UB 还需要再降多少才会硬化下一条（raw 单位），小于等于 0 才会跨过 |
| `harden_goal_interval` | 当前 `UB - LB`（raw 单位） |

## 2. 结果：24 个被接受轮次里没有一次触发新的硬化

HybridSelective 的 50 个运行共 24 个「SPB 改善被接受」的轮次：

| 观察 | 数量 |
|---|---|
| 改善后跨过了下一个硬化阈值 | **0/24** |
| 改善后仍未跨过阈值 | 24/24 |
| 但缩短了到阈值的距离 | 24/24 |

单轮改善能走完到阈值距离的比例：**中位 33.5%**（p10 0%，p90 87.3%）。
被接受轮次开始时，UB 到阈值的相对距离（gap / UB）中位为 **18.27%**。

## 3. 真正发生硬化的运行都发生在 CASH 自己的第一个窗口

50 个运行里真正硬化过软子句的：HybridSelective 6 个、CASH 4 个。时间线：

| 实例 | 硬化时刻 | 硬化条数 | 当时 UB | 之后 SPB |
|---|---|---|---|---|
| `drmx-cryptogen_wt-geffe128_1` | t=30.0（首轮交接前） | **7444** | 893（从 11919244 降下来） | 893 到 826 |
| `frb_wt-frb25-13-1` | t=6.2（早于首轮交接） | **10599** | 302（从 3455599 降下来） | 301 到 300 |
| `abstraction-refinement_wt-downcast-pmd` | t=30.0 | 419 | 5115（从 1762725 降下来） | 5115 到 4624 到 4524 |
| `causal-discovery_wt-causal_Meta_7_528` | t=5.6 / 11.4 | 92 / 102 | 63768 到 55120 | 首轮未改善 |

规律一致：硬化发生在 CASH 自己的第一个窗口里，它把 UB 从 10^6~10^7 量级压到 10^2~10^3 量级，
一次硬化几千条；等 SPB 上场时 UB 已经贴着阈值，SPB 的改善只是继续拉近距离。

## 4. 结论

- 到目前为止，**SPB 给出的上界没有直接推导出任何必须硬化的软子句**（0/24）。
- 它做的是把 UB 朝硬化阈值推进：每轮走完剩余距离的中位 33.5%。按选择性调度（首轮 + 至多一次重试），
  多数运行只走 1~2 轮，走不到阈值是必然的。
- 这正是 A1（阈值感知目标）的立足点：既然只有跨过阈值才改变精确搜索，就应把目标设为
  「把 UB 压到 `LB + 下一条权重` 以下」（严格小于）交给 SPB，达到即提前返回；
  这同时解决定时间搜索的浪费（拿到最好解之后中位还空跑 6.07 秒）。
- A1 的可证伪判据：若目标设为跨过下一个阈值后 `harden_count` 仍不增长，说明该阈值在当前权重分布下不可达，
  应改为「下 k 个阈值」。
